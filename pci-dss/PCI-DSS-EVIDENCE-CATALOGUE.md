# PCI DSS Evidence Governance Catalogue

[PCI DSS resources](README.md)

Illustrative evidence categories for coordinating assurance. This is not an exhaustive evidence request list, technical collection guide, or mapping to individual PCI DSS requirements.

| Governance / assurance area | Example record to request | Quality question |
| --- | --- | --- |
| Scope | Approved inventory, scope rationale, specialist validation references | Are dependencies and exclusions supported? |
| Ownership | Control register and accepted responsibilities | Are all applicable controls assigned? |
| Policy oversight | Approved policy versions and review decisions | Were relevant versions effective during the period? |
| Control operation | Owner-provided operation and review records | Do scope, population, period, results, and failures remain visible? |
| Specialist assurance | Assessment reports and remediation verification | Does scope cover the obligation being evaluated? |
| Service providers | Service-specific assurance and responsibility matrix | Are customer obligations and gaps explicit? |
| Risk analysis | Applicable analysis record and approval | Does the analysis address the specific permitted purpose? |
| Findings | Corrective action records and closure evidence | Has resolution been independently verified? |
| Training / accountability | Assigned population and completion records | Are omissions and applicable role requirements addressed? |
| Program review | Management decisions and action tracking | Are material gaps escalated and followed up? |

## Evidence request record

| Request ID | Exact requirement / version | Control ID | Required scope / population / period | Owner / custodian | Due date | Private evidence reference | Received date | Reviewer | Quality result / limitations | Finding ID |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | | | | |

Define requests against applicable official testing procedures and the assessment plan. Retain provenance, timestamps, and version history. Limit access and retention according to approved information handling requirements.

Check relevance, completeness, authenticity, period coverage, and visible results. Missing or inadequate evidence must remain an open request or finding; an owner attestation does not automatically resolve it.

Use the [shared evidence register](../controls-and-evidence/README.md) and [assurance workflow](../assurance/README.md). Authoritative source: [PCI SSC Document Library](https://www.pcisecuritystandards.org/document_library/).
